2. Công nghệ Cốt lõi (Tech Stack)

Lựa chọn công nghệ hiện đại, bền vững và tuân thủ tiêu chuẩn Web
02 / CÔNG NGHỆ
Backend & SSR

Express 5.3 + express-handlebars 9.0

TypeScript Strict ở chế độ NodeNext ESM. 2 layout độc lập (Public & Admin) cùng hệ thống helpers định dạng VND, phân quyền can.

Cơ sở dữ liệu & Auth

PostgreSQL + Prisma ORM 7

Sử dụng adapter chính thức @prisma/adapter-pg trên nền Supabase. Quản lý phiên làm việc qua signed cookie và lưu trữ ảnh trên Supabase Storage.

Giao diện & Styling

Tailwind v4 + CSS Viết tay

Tailwind CSS v4 tối ưu hóa dựng nhanh form admin; style.css và admin.css tùy biến design system, chuyển theme Dark/Light không phụ thuộc JS.

🛡️ Lớp phòng thủ Bảo mật Toàn diện
Zod 4.6

Kiểm tra toàn bộ biến môi trường lúc boot và dữ liệu form gửi lên.

csrf-csrf 4.0

Double-submit CSRF cookie token, bảo vệ 100% form POST/PATCH/DELETE.

Helmet 8.3

Thiết lập các HTTP security headers (chống clickjacking, sniff mime-type).

Rate Limit Tự Viết

Middleware in-memory khóa brute-force IP đối với các route nhạy cảm /login & /register.

Ghi chú diễn giả
Giải thích: Nhóm nâng cấp lên Express 5 mới nhất cùng Prisma 7 với adapter PostgreSQL driver. Không dùng thư viện rate-limit nặng mà tự code middleware in-memory trượt cửa sổ thời gian.

🔄 Chống Trùng Lặp Thông Minh
  • Tự động tăng hậu tố slug nếu bị trùng: pho-bo-2, pho-bo-3.
  • Chống trùng nguyên liệu trong cùng một món trên form (ngăn lỗi vi phạm composite PK).
  • Chống trùng tên nguyên liệu không phân biệt hoa thường (mode: 'insensitive').
🗑️ Xóa Mềm An Toàn & Trang Xác Nhận
  • Nút xóa dẫn đến trang xác nhận riêng GET /admin/.../:id/delete.
  • Tuyệt đối không thực hiện xóa dữ liệu bằng yêu cầu GET.
  • Xác nhận xóa sẽ gửi yêu cầu DELETE (cập nhật deletedAt), có nút khôi phục lại khi cần.
Ghi chú diễn giả
Nhấn mạnh rằng form HTML chỉ hỗ trợ GET và POST, nhóm đã viết middleware method-override bắt trường `_method` để hỗ trợ PATCH/DELETE đúng chuẩn RESTful. Phản hồi 303 Redirect là tiêu chuẩn công nghiệp chống double-submit.

Kiểm Tra File Upload Bằng Magic Bytes

Không tin tưởng phần đuôi mở rộng (.jpg/.png) do trình duyệt gửi lên:

  • JPEG: Quét 3 bytes đầu tiên 0xFF, 0xD8, 0xFF.
  • PNG: Quét 8 bytes chữ ký nhị phân 89 50 4E 47 0D 0A 1A 0A.
  • WebP: Quét định dạng container RIFF....WEBP.
  • Giới hạn dung lượng: Trần Multer 5MB, ảnh hợp lệ ≤ 2MB.
Ngăn chặn triệt để mã độc giả mạo đuôi ảnh
Phòng Thủ CSRF Hai Lớp (Double-Submit)

Bảo vệ 100% các thao tác thay đổi dữ liệu mà không cần duy trì session server:

  • Tự động sinh signed cookie định danh trình duyệt ẩn danh (sid).
  • Ràng buộc token CSRF ẩn trong form ({{csrfToken}}) với cookie.
  • Bảo vệ an toàn mọi form POST/PATCH/DELETE trước tấn công giả mạo yêu cầu.
Ghi chú diễn giả
Giải thích hàm `saveWithImage` trong `src/lib/storage.ts`: đây là pattern giao tác giúp storage không bị rác (orphan files) nếu quá trình tạo món trong DB bị lỗi. Magic-bytes bảo vệ server không bị hacker upload file shell php/sh giả mạo đuôi png.
