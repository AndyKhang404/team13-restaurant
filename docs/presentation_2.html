4. Migration, CHECK & Row Level Security

Chốt chặn cuối cùng nằm ở chính cơ sở dữ liệu
04 / DB HARDENING
ALTER TABLE "dishes" ADD CONSTRAINT "dishes_price_check"
  CHECK ("price" >= 0);
ALTER TABLE "dish_ingredients"
  ADD CONSTRAINT "dish_ingredients_quantity_check"
  CHECK ("quantity" > 0);
ALTER TABLE "dishes" ENABLE ROW LEVEL SECURITY;
CREATE POLICY "public read dishes"
  ON "dishes" FOR SELECT TO anon, authenticated
  USING ("deleted_at" IS NULL);
🔒 Nguyên tắc
  • Mọi thay đổi schema qua migration có version (4 migration)
  • CHECK: giá, tồn kho, số năm KN, thời gian chế biến, định lượng
  • RLS bật cho 5 bảng; xóa mọi policy ghi từ client
  • profiles: chỉ đọc hồ sơ của mình (auth.uid() = id)
  • Storage: public read, upload chỉ qua server
Phòng thủ nhiều lớp: Zod ➔ RBAC ➔ CHECK ➔ RLS
Ghi chú diễn giả
Nếu có client nào gọi thẳng Supabase, RLS vẫn chặn ghi; CHECK chặn dữ liệu sai dù validation ứng dụng bị bỏ qua.

6. RBAC theo permission

Code kiểm tra permission, không bao giờ kiểm tra tên role
06 / PHÂN QUYỀN
export type Permission =
  | 'admin:access'
  | 'dish:create' | 'dish:update' | 'dish:delete'
  | 'chef:create' | ... | 'ingredient:delete'
  | 'user:manage';

ROLE_PERMISSIONS = {
  ADMIN:    [admin:access, ...CONTENT, user:manage],
  STAFF:    [admin:access, ...CONTENT],
  CUSTOMER: [],
};

router.post('/', requirePermission('dish:create'), ...)
🛡️ Hành vi
  • Chưa đăng nhập → 401 UNAUTHORIZED
  • Thiếu quyền → 403 FORBIDDEN
  • SELF_ROLE_CHANGE: không tự đổi role của mình
  • LAST_ADMIN: không hạ cấp admin cuối cùng
  • RequireAuth ở client chỉ để UX — API vẫn cưỡng chế
Ghi chú diễn giả
Thêm quyền mới chỉ cần thêm vào union Permission rồi gán cho role; handler không đổi.

7. Bảo mật HTTP

CSRF double-submit, CORS whitelist, rate limit
07 / BẢO MẬT
🧾 CSRF
  • csrf-csrf double-submit gắn cookie sid ký
  • Token: header x-csrf-token hoặc _csrf
  • Request Bearer được miễn (không tự đính kèm cross-origin)
  • Lỗi → 403 CSRF_INVALID
🌐 CORS
  • Whitelist: APP_URL, SPA_ORIGIN/CORS_ORIGIN
  • localhost chỉ khi không phải production
  • credentials:true, phản chiếu origin (không *)
  • Expose x-csrf-token
🚦 Rate limit & khác
  • Cửa sổ 60s, tối đa 20, khóa ip:path
  • Áp cho /auth/login, /auth/register → 429
  • Dọn map khi > 5000 key
  • helmet, safeNext() chống open redirect
  • paramId(): UUID sai → 404 thay vì 500
Ghi chú diễn giả
Giới hạn đã biết: rate limiter in-memory, chỉ phù hợp một tiến trình Node; nếu scale ngang cần Redis.

8. Hợp đồng API & xử lý lỗi

Hai nhánh lỗi: nghiệp vụ (HTTP 200) và kỹ thuật (status thật)
08 / API CONTRACT
Thành công
200
{ "ok": true,
  "data": { ... } }
Lỗi nghiệp vụ
200  (validation, 404, 409)
{ "ok": false,
  "error": { "code": "VALIDATION_FAILED",
    "message": "...",
    "fields": { "name": "..." } } }
Lỗi kỹ thuật
401 / 403 / 429 / 5xx
{ "error": { "code": "FORBIDDEN",
    "message": "..." } }
// không có "ok"
🖥️ Phía server
  • HttpError(status, msg, code, fields, business)
  • ApiErrorCode gõ kiểu: VALIDATION_FAILED, ALREADY_EXISTS, LAST_ADMIN…
  • Production che message lỗi 5xx
⚛️ Phía client
  • apiFetch<T> bóc envelope
  • Nghiệp vụ → ApiError (có fields)
  • Kỹ thuật → HttpError
Ghi chú diễn giả
Client rẽ nhánh theo error.code thay vì status; lỗi kỹ thuật giữ nguyên status để proxy/monitor nhận diện.

const blankToUndefined = v =>
  v == null || (typeof v === "string" &&
   ["", "null", "undefined"].includes(v.trim().toLowerCase()))
    ? undefined : v;

export const optionalInt = (label, min = 0, max?) =>
  z.preprocess(blankToUndefined,
    z.coerce.number().int().min(min).optional());

toFieldErrors(zodError)
// { "name": "...", "ingredients.0.quantity": "..." }
✅ Điểm chính

  • checkbox: on/true/1 → true
  • Lỗi theo path → error.fields để UI tô đúng ô
  • Validate ảnh + dòng nguyên liệu song song với schema, gộp một lượt lỗi
Ghi chú diễn giả
blankToUndefined giải quyết việc form gửi chuỗi rỗng hoặc "null" cho trường tùy chọn.

// Retry chỉ cho GET/HEAD, tối đa 5 lần
const maxAttempts = method === "GET" || method === "HEAD" ? 5 : 1;

🔁 Hành vi
  • Gắn Authorization: Bearer + x-csrf-token (phương thức không an toàn)
  • credentials: "include"; JSON hoặc FormData

  • VITE_SERVER_URL bắt buộc: fail-fast khi thiếu
Ghi chú diễn giả
Retry chỉ với thao tác idempotent giúp SPA sống sót khi API đang khởi động lại ở dev mà không nhân đôi thao tác ghi.
